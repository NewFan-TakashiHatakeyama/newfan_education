# 全実装PdMレビュー P0・P1修正対応

対象：`outputs/review-ai-project/adversarial-review-2/PdM敵対的レビュー_全実装_2026-09-11.md` のP0 2件・P1 16件。
更新日：2026-09-11。本番へのデプロイ・本番DB移行は実施していない。

## 提供範囲と変更後の動作

公開自己登録は招待参加専用とした。管理者が発行したリンクの所持、メール一致、7日以内、未使用であることをサーバーで確認する。参加者が所属・権限を入力する経路は拒否する。新しいテナントの公開セルフサービス作成は提供しない。

安全な別実行サービスと検証済みの評価器が存在しないため、演習コードの実行とAI採点は未提供とした。提出内容の保存・閲覧とメンターレビューは継続する。APIホスト内のexec、子プロセスへのフォールバック、Dockerソケットを使った提出コードの実行は削除した。

通知はアプリ内のみ提供する。メール・pushの未送信を配信成功として記録せず、設定画面でも選択できない。新しいアプリ内通知は受信箱と完了記録を同じDBトランザクションに保存するので、通知workerの起動に依存しない。招待は自動メール送信ではなく、管理者がリンクを取得して本人へ渡す方式である。

適合度は技能タグの一致率による参考値であり、職務適性や案件成功確率の推定ではない。最終判断は責任者が行う。

## 導入時に必要な対応

依存パッケージに`reportlab`を追加した。APIを更新する際は依存パッケージも更新し、既存DBにはAlembic `20260911_0005`を適用する。Web/APIは同時に更新する。旧Webや旧APIクライアントがrevisionなしで台帳を保存する操作は拒否される。

移行は既存セッションを失効させ、旧R19任命は再任命が必要になる。リスク確認も再確認待ちへ変更する。旧能力評価を削除せず、その後の版を追記可能にする。旧AI証跡は`unverified`へ変更する。既存の未実装チャネルの配信は実受信を証明できないため失敗扱いとし、アプリ内のみの未処理ジョブは受信箱へ保存する。

移行前にバックアップと対象利用者の棚卸しが必要。`apps/api/tools/audit_membership.py`は明示したDATABASE_URLに読み取りだけを行い、招待受理の監査証拠がない既存利用者をreviewRequiredとして出力する。正規の初期管理者もこの対象になるので、不正と自動断定したり自動削除したりしない。管理者が所属・権限を確認する。

従来メモリだけにあった記録は、過去のプロセス終了時に失われた分を復元できない。新実装は今後の記録を永続化する。取消済み評価を含む履歴を一意な現行1行に戻すことはできないため、移行のdowngradeは拒否する。必要時は事前バックアップからの復元を別途検証する。
