# 成果物の書式仕様（lintが読む形）v1.2.0

完成例の全文を読む代わりに、この仕様で書式を固定する（粒度は examples.md の抜粋で確認する）。lint（scripts/lint_curriculum.py）は下記の書式を前提に機械照合するので、見出し・表・時間表記は変えない。

## 共通

- UTF-8 Markdown、日本語。架空の会社・人物・数値・判定は「架空」と明示。原典の転記／教材設計上の提案／架空ケースを区別する。
- 法令等は、レジストリ（`_sources.json` の facts_text・cards）または一次資料で確認した内容だけを確認日付きで書く。`unverified`（二次資料由来）と entry のない話題は「未確認・要法務確認（根拠：…）」と書く。個別案件への当てはめは必ず「候補／暫定／要法務判定」と書く（断定は不可）。
- ID体系：目標 `Sxxx-Ln-Oyy`、単元 `Mxx`、演習 `Exx`、様式 `T1〜T12`（社内Tier T0〜T3と区別し、冒頭で注記）、抜粋カード `Kxx`、評価 `A1/A2/A3`、役割 `Rxx`（原典06シートのID）。spec の roles／templates／cards に書いたIDは 03 に同じ見出し・行として現れなければならない（lint）。
- 見出しのIDの直後は半角スペース（`## M01 単元名`、`## A1 Lv1修了評価`、`## 3. A1 採点`）。`## A1修了評価` のように続けると lint が見出しを見つけない。
- 分量の目安（実測に基づく式）：4本合計 ≈（総分数÷100）×4〜6KB を基本とし、法令の抜粋カード・照会応答カード・後輩役カードを要する教材（`_sources.json` の legal_content=true、または A3 に指導課題がある）は ×9〜11KB。配分は 01:02:03:04 ≈ 1:2:2.3:2.5。参考：S001 1,800分・約73KB（4万字）、S002 2,265分・約248KB（11万字）。量ではなく「受講者が教材だけで演習に着手でき、講師が採点できる」ことで判断し、目安を守るために模範解・応答カード・付録を削らない。
- 生成された骨組み（`_tables.md`）の「記入」はすべて埋める（`：記入。`、`／記入`、`| Rxx | 記入 |` が残ると lint エラー）。受講者が埋める様式の空欄行 `| 記入 | 記入 |` は正当。

## 01-design.md

```
# Sxxx カリキュラム設計書
教材名／教材版／制作基準／作成日／最終確認／状態（試行授業・実務認定は未実施と明記）
## 1. 原典と位置づけ   … 原典ファイル名・SHA-256、原典項目表（定義・Lv1〜3・能力証拠・関連タスク）、出典セル、接続する原典シートの表、
                        「本講座が担うこと／前提として説明すること／他スキルへ委ねること」（_tables.md の3行）と権限境界（判定の確定者）
## 2. 一次資料の確認（確認日 YYYY-MM-DD） … 法令等を扱う場合のみ。表：資料｜原典の記載（_context.json の source_sheet／registry の origin）｜確認した現行内容｜原典との差｜教材での扱い。
                        末尾に未確認事項と、stale な entry の再確認予定
## 3. 対象者・前提・範囲 … 対象ロール、前提知識、本講座が担う／前提として説明する／他スキルへ委ねる（S番号とタスクID）
## 4. 学習目標         … 表：| ID | 条件・入力 | 観察する行動／提出物 | 品質・権限境界／典型失敗 |（_tables.md。全目標IDが行として存在。lint）
## 5. 単元と時間       … 表：| 単元 | Lv・目標末尾 | 内容 | 時間内訳 | 演習・主な提出物 | 修了評価 |、行は `| M01 | 1・O01 | … | 25/15/30/20/0 = 90 | E01 … | A1 |`
                        （lint は Lv・目標末尾（O01〜O03／O01、O04 の表記可）・分数・演習IDを curriculum.json と照合）
                        直後に `Lv1=…分、Lv2=…分、Lv3=…分、合計N,NNN分` と区分別合計（_tables.md を貼る）
## 6. 対応と認定       … 原典の判定エビデンス→教材提出物の対応表、各評価の合格基準（観点名・必須問・重大誤判断0件）、尺度の説明
## 7. 実施方法         … 日程案、講師要件、必要物、評価中の許容支援、不合格時の扱い、実務確認への接続（28シート）
## 8. 更新管理         … 初版変更理由、仮定、改正検知時の更新方法、制作台帳への参照
```

## curriculum.json

`scripts/harness.py build` が `_spec.json` から生成する。手書きしない。assessments には `observation_points`（採点表の行名）と `minutes`（当該Lvの単元の評価分の合計）、全体に `templates`／`cards`／`roles`（03との照合用）、`review.self_check`（finish が自己点検完了日を記録。未完なら "pending"）を含む。

## 完成例

粒度の見本は examples.md（S001 の証拠パック・A2・A2採点、S002 の後輩役カード）にある。法令の抜粋カードの見本は `_sources.json` の cards（S002 K01〜K11）。完成例の全文は読まない。
